# MyLLMService — проверка стиля текста

Gradio-сервис проверяет пользовательский текст на соответствие выбранному стилю и возвращает замечания от GigaChat.

История изменений проекта ведётся в [ChangeLog.md](ChangeLog.md).

## Сценарий и архитектура

Поток обработки:

1. Gradio принимает текст и стиль: `научный`, `официально-деловой` или `разговорный`.
2. `StyleReviewHandler` валидирует ввод до вызова внешней модели.
3. `TextStyleService` строит prompt, проверяет TTL-кеш и запускает LLM-модуль.
4. `LLMClient` вызывает GigaChat с timeout и ограниченными retry.
5. Ответ очищается, проверяется и возвращается в Markdown-поле интерфейса.

Основные слои:

- `gradio_app.py` — интерфейс;
- `app/services/text_style_service.py` — бизнес-логика и обработка сценария;
- `app/llm/prompt_builder.py` — системная инструкция и пользовательский prompt;
- `app/llm/client.py` — вызов GigaChat и классификация ошибок;
- `app/cache/memory.py` — TTL-кеш повторяющихся запросов;
- `app/config/settings.py` — конфигурация через переменные окружения;
- `tests/` — автоматические тесты.

## Установка и запуск

Требуется Python 3.10+.

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполните `AUTHORIZATION_KEY` в `.env` и запустите:

```powershell
python gradio_app.py
```

После запуска откройте адрес Gradio, указанный в консоли.

## Использование

Введите текст длиной от 1 до 10000 символов, выберите стиль и нажмите «Проверить стиль». Ответ содержит замечания по тексту: проблемный фрагмент, объяснение и вариант исправления. Если проблем нет, модель сообщает `Замечаний нет`.

Пример результата:

```markdown
- **Проблемный фрагмент:** «Данный текст является очень важным».
  **Замечание:** конструкция избыточна для официально-делового стиля.
  **Вариант:** «Этот текст важен».
```

## Валидация и ошибки

Пустой текст не отправляется в модель и возвращает: `Напишите текст для проверки.`

Текст длиннее 10000 символов возвращает: `Слишком длинный текст — сократите или разбейте на части.`

Ошибки внешней модели не показывают traceback или секреты:

- ошибка доступа: `Не настроен доступ к сервису.`;
- HTTP 5xx: `Сервис временно недоступен. Попробуйте позже.`;
- timeout или сеть: `Не удалось получить ответ. Попробуйте ещё раз.`;
- пустой ответ: `Пустой ответ модели. Попробуйте проверить другой текст.`

## Конфигурация и секреты

Настройки находятся в `.env`, а шаблон — в `.env.example`. API-ключ не хранится в исходном коде и исключён из Git. Таймаут запроса к LLM составляет 15 секунд и может быть изменён через `LLM_TIMEOUT`. Также поддерживаются URL API/OAuth, модель, количество retry, задержка retry, TTL кеша и путь к JSON-логам.

Логи пишутся в консоль и `logs/service.log`. Фиксируются входные этапы, prompt, ответ модели, ошибки, cache hit/miss и длительность операций.

## Кеширование

Ключ кеша учитывает исходный текст, выбранный стиль, модель, температуру и системный prompt. TTL по умолчанию — 10 минут. Повторный идентичный запрос не вызывает модель повторно и записывает событие `cache_hit`.

## Тестирование

Подробное описание сценариев и результатов тестирования находится в [TESTING.md](TESTING.md).

```powershell
python -m unittest discover -s tests -v
python -m compileall -q app tests gradio_app.py
```

Проверяются корректный сценарий, пустой и слишком длинный ввод без вызова модели, кеширование и fallback при сетевой ошибке.

## CI

GitHub Actions workflow находится в `.github/workflows/ci-cd.yml`. Он устанавливает зависимости, запускает Ruff, тесты и проверку компиляции. Workflow не требует API-ключа, потому что тесты используют mock LLM.
